# LESSONS — co nás stálo čas (krátce, jeden řádek na věc)

- iPad Safari potřebuje HTTPS kvůli SharedArrayBuffer (vlákna). LAN http nefunguje → cloudflared tunel.
- WGSL cache je v IndexedDB → pro test „poprvé“ smazat data webu nebo anonymní panel.
- Dlouhé buildy pouštět přes `setsid nohup … &` a číst log; neblokovat terminál.
- Repo klonovat do WSL (`~/`), ne do `/mnt/c/…` — build přes Windows disk je mnohonásobně pomalejší.
- Build blender-wasm od nuly: čekej 4 skryté chyby linku (host python, duplicitní expat, emdawnwebgpu port, brotli) — všechny teď v `cmake/blender-wasm-cache.cmake`. `ninja` selhání na `bin/blender.js` ignorovat, link dělá `link_blender_release.sh`. Ztraceno ~40 min.
- Hypotézy z PLAN.md (depth range) ověř MĚŘENÍM dřív než kódem: `WGPU_LOG_DRAW` (přes `window.__CAPENV`) + experiment „vypnout depth“ + „natvrdo fialová barva ve fragment shaderu“ rozlišily příčinu za ~1 h; čtení kódu ji nenašlo.
- Screenshoty canvasu: Chrome ve WSL (SwiftShader) kreslí canvas BÍLE → testuj ve Windows Chrome přes `scripts/p2_win.sh` (node.exe + playwright-core, `C:\Users\<u>\p2win`).
- Komentáře ve `.glsl` shader_tool maže → marker `/* DEBUG */` v shaderu v buildu není; shadery jsou v targetu `bf_draw_shaders`. `git push` do forku Blenderu: `GIT_LFS_SKIP_PUSH=1`.
- 17. 10.: WGSL seed/IndexedDB cache nikdy nefungovala — Blender běží na pthread workeru (`PROXY_TO_PTHREAD`), `globalThis` z `main.js` tam není. Cokoli z JS pro C++ musí jít sync XHR / BroadcastChannel, ne přes globál stránky.
- 17. 10.: `--python-expr` ve wasm: bez `sys.stdout.flush()` se výstup nikdy nedostane do konzole stránky. Detektor první verze odmítl i vestavěný startup.blend (legitimní duplicitní adresy) — porovnávat RAW 64bit hodnoty, ne zkrácené.
- 17. 10.: Jakákoli změna GLSL preambule (`webgpu_glsl_patch`) mění klíče WGSL cache → seed je k ničemu; po změně vždy `scripts/wgsl_seed_win.sh seed` (2×) a `verify`.

- 17. 10.: PNG save padal na „tEXt: invalid keyword“ (~1,5 h). Nehledat v libpng: pomohl debug fprintf do libpng → klíč byl prázdný → OIIO `ustring::string()` prázdné kvůli libc++ hacku. Knihovní chyby ladit printfem v deps/src + `build_*.sh` + `link_blender_release.sh` (bez ninja).

- 17. 10.: numpy do wasm přes meson cross + `-sFAKE_DYLIBS=1` (emsdk 6: `-shared` = SIDE_MODULE) vyšlo na první pokus za ~10 min díky plánu od architekta; Python add-ony ladit rovnou přes `ops_win.sh` testy (chyby jdou jako text, ne screenshot).

- 17. 10.: `scripts/link_blender_release.sh` kopíruje `web/wgsl-cache.json` do `demo/public/` (přepíše seed!) — seed upravuj v obou místech (wgsl_seed_win.sh to dělá). Seed pro náhledy materiálů (mattab_seed.sh) NEPOMOHL: s cache 12 s vs 6 s bez; pipeline compile je úzké hrdlo, ne překlad.
- (17. 10. večer) Playwright `click({modifiers:["Control"]})` v Blenderu nestačí → Ctrl+klik jen přes `keyboard.down("Control")` + klik + `up`. Souběžně: po `open_mainfile` z Python timeru přestane `bpy.context.object` existovat → používat `view_layer.objects.active`.
- (17. 10. večer) V Blenderu 5.x je akce vrstvená: `action.fcurves` neexistuje (AttributeError v timeru tiše zabije celý probe a test vypadá „zamrzle“). Při NaN/null v měřených hodnotách nejdřív zkontrolovat `… ERR` řádek.
- (17. 10. večer) Env proměnné do Windows node z WSL: nutné `WSLENV=NAZEV:NAZEV2` + v `*_win.sh` předat přes `set NAZEV=%NAZEV%&&` (a v JS ošetřit nenastavené `%NAZEV%`).
- (17. 10. večer) Test barvy materiálu: výchozí kostka už má slot 0 (`materials.clear()` před `append`), splash screen zakrývá viewport (Escape), a osvětlená červená v Material Preview je oranžová → porovnávat poměrem, ne pevným prahem.

- 18. 10.: hledání zamrznutí operátoru (~1,5 h): `fprintf`+`fflush(stderr)` mezi řádky funkce + `OPS_ALL=1` v `ops_test.mjs` najde přesný řádek za 3–4 buildy (`ninja bf_editor_uvedit` + `link_blender_release.sh`, ~4 min/cyklus). Zamrzla `Array<Struct s bitfieldy>(n, {false,false})`, ne algoritmus. Dřív zkusit sweep (`scripts/*_ops_sweep_win.sh`) než číst algoritmy.
- 18. 10.: zapnutí vypnutých funkcí buildu je levné, když je zdroj bundlovaný: `WITH_BULLET`, `WITH_QUADRIFLOW`, `WITH_MOD_FLUID` (extern/) = jen `cmake build-blender -DWITH_X=ON` + `ninja` (~10–15 min) + `link_blender_release.sh`; OpenVDB = nový dep `scripts/build_openvdb.sh` (~8 min, bez Boost) + celý ninja (~70 min). Nejdřív zkusit, ne ptát se. Zálohovat `demo/public/blender.js|wasm.zst` do `out/bak*`.
- 18. 10.: wasm je přísnější než x86: RNA update funkce se špatným počtem parametrů (`PROP_CONTEXT_UPDATE` ⇒ 2 parametry) = pád „function signature mismatch“. Statická kontrola `scripts/check_rna_update_signatures.py` (v `regress_all`) to hlídá.
- 18. 10.: falešné FAIL ve fuzzu = špatná kontrola živosti (fuzz změní layout, MMB tah v Outlineru nic nepřekreslí) — vždy se podívat na `out/win/ui_fuzz_end.png`, než se hledá „zamrznutí“.
- 23. 10.: `wgpuBufferDestroy` přidaný do M2 (~1,5 h): backend spoléhá na „use-after-release“ (uvolněný buffer zůstává použitelný do GC). Zničení rozbilo parity #12/#17/#20 BEZ jediné chyby v konzoli. Pomohlo: runtime přepínače `WGPU_NO_DESTROY[_USAGE]` + `PARITY_ND/NDU` v `parity_win.sh` (bisekce podle `usage` flagů bufferu, 1 link ~4 min). Příčiny: (1) uniform arena — shader si drží `pc_slice_buf_` po celou epochu → chunk smí pryč až v `uniform_arena_reset`; (2) VBO (Vertex|CopySrc) zničení rozbije nově přidaný mesh — příčina neznámá, VBO se nechávají GC.
- 23. 10.: telemetrie nesmí být zapnutá v Playwright testech (`navigator.webdriver`) — mění časování. `Module.wasmMemory` na main threadu není exportovaná a čtení volá `abort()`.
- 25. 10.: `drag_win.sh` ukazuje 3–10 FPS i na kostce v Object módu (api_ms < 1 ms, 24 passů) — pravděpodobně omezuje samotná dávka událostí Playwright (`mouse.move` čeká na odpověď rendereru), ne Blender. FPS z drag testu NEBRAT jako výkon; slouží jen k počítání bufferů (live/destroyed). Skutečný výkon měř `drawtime_win.sh` (ms/frame). Ztraceno ~40 min.
- 25. 10.: hledání „proč první Subsurf trvá 10 s“ (~1,5 h): časové laps (`std::chrono` + `fprintf(stderr)` za `getenv`) přímo v C++ funkci (OpenSubdiv `evaluator_impl.cc`) našly viník za 4 buildy (ninja jen dotčená lib + `link_blender_release.sh` ~2 min). Python `time.time()` kolem `evaluated_depsgraph_get()` rozdělí „kde“ rychle. Pozor: `ninja` cíl musí doběhnout PŘED linkem (jinak se linkuje stará lib → stejná čísla).
- 25. 10.: drag_win/ruční node testy 'visely' (~1 h ztráceno): timeout zabije jen cmd.exe, node+Chrome zůstanou a další běh je pomalý/zamčený. Před každým během: taskkill.exe /F /IM node.exe /IM chrome.exe; timeout dávat ≥400 s (studený start ~100 s); výstup přes tr buffer = prázdný log při kill.
